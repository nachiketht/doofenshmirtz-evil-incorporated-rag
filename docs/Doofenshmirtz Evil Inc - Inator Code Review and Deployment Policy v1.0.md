# Doofenshmirtz Evil Incorporated
## Inator Code Review and Deployment Policy — Version 1.0

## 1. Purpose

Modern inators run software. This policy explains how that software is reviewed and deployed, so that no inator ships with a bug that makes it shoot rainbows.

## 2. Scope

This policy applies to all firmware, apps and scripts that control an inator, robot or self-destruct mechanism.

## 3. Code Review

**3.1 Reviewers.** Every change needs approval from one other engineer. Changes to self-destruct logic need two approvals.

**3.2 Review Time.** Reviews should be completed within 1 business day, or before the next scheme, whichever comes first.

## 4. Deployment

**4.1 Deploy Windows.** Inator software is deployed on Tuesdays and Wednesdays only. Deploying on a Friday is forbidden.

**4.2 Rollback.** Every deployment must have a rollback plan that works even if a platypus has already unplugged the inator.

## 5. Testing

Automated tests must pass before deployment. Testing in production is allowed only on the Tri-State Area's least important bridge.

## 6. Acknowledgment

Merging any code constitutes acknowledgment of this policy.
